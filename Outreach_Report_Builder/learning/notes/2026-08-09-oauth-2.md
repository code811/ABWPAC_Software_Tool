## Current Mental Model
Authentication confirms the identity of the user, Authorization validates the permissions granted. An OAuth 2.0 example follows the Resource Owner accessing an Application. They're redirected to the Authorization Server where they grant certain permissions to the Client. Suppose the Resource Owner allows; the Authorization Server responds with a temporary Authorization Code to the Client. The Client exchanges this code with the Authorization Server for a temporary Access Token and optionally a Refresh Token. The Authentication and Access Token is used in the Client's request to the Resource Server, so that it is able to identify and verify the request, to give a response. This transaction occurs at the moment; if another request is needed later, the Refresh Token is used to grant the Client another Refresh Token from the Authorization Server to repeat a request.
